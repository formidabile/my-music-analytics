# Импортёр музыкальной статистики Excel → SQLite

Импортирует годовые Top-50 из единственной Excel-книги проекта в нормализованную SQLite-базу. Пользователю не нужно передавать пути или параметры командной строки.

## Структура проекта

```text
project/
├── data/
│   ├── music_statistics.xlsx
│   └── music_predictions.xlsx
├── database/
│   ├── schema.sql
│   └── music.db              # создаётся автоматически
├── src/
│   ├── database.py
│   ├── importer.py
│   ├── analytics.py          # расчёт аналитических показателей
│   └── report.py             # генерация Excel-отчёта
├── reports/
│   └── music_analytics.xlsx  # создаётся генератором отчёта
├── tests/
├── importer.py               # запуск только импорта
└── main.py                   # точка входа приложения
```

Положи фактические рейтинги в `data/music_statistics.xlsx`, а прогнозы — в `data/music_predictions.xlsx`. Оба пути фиксированы относительно корня проекта; имена файлов не нужно передавать при запуске.

## Структура Excel-книги

- отдельный лист на каждый год рейтинга (`2023`, `2024`, `2025` и т. д.);
- пять столбцов строго в указанном порядке: `Исполнители`, `Песня`, `Язык`, `Страна`, `Год`;
- несколько исполнителей, языков или стран разделяются точкой с запятой (`;`);
- порядок строк данных задаёт позицию в рейтинге: первая песня — позиция 1;
- на каждом листе должно быть ровно 50 полностью заполненных строк данных.

Для совместимости принимаются также прежние варианты заголовков: `Артисты`, `Название`, `Языки`, `Страны`, `Год выпуска`.

## Установка и запуск

Требуется Python 3.10 или новее. Установи зависимости один раз:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Импорт рейтингов и прогнозов:

```bash
python import_data.py
```

Импорт стримингов (после импорта рейтингов, поскольку используется общий справочник исполнителей):

```bash
python -m src.streaming
```

Запуск локального веб-сайта:

```bash
python main.py
```

Затем откройте `http://127.0.0.1:8000` в браузере.

Аргументы командной строки не используются. `python import_data.py` и `python importer.py` читают `data/music_statistics.xlsx` и используют `database/music.db`.

## Поведение при запуске

1. Если базы ещё нет, она создаётся по `database/schema.sql`.
2. Импортёр проверяет всю Excel-книгу: обязательные поля, годы, структуру листов, Top-50, дубли и внутренние конфликты.
3. Если хотя бы один год из книги уже есть в базе, импорт по умолчанию останавливается. Ничего не пропускается и не перезаписывается.
4. При конфликте метаданных с уже сохранённой песней импорт останавливается и выводит список конфликтов. Данные базы не изменяются.
5. Изменения выполняются одной транзакцией. При ошибке во время записи транзакция откатывается целиком.

Повторный запуск безопасен: он не создаёт дубликаты, а сообщает, что рейтинг за этот год уже существует. Для полной замены рейтингов из книги требуется явное указание `replace_existing=True`. Например, из Python:

```python
from src.importer import run_project_import

run_project_import(replace_existing=True)
```

Обычный запуск `python import_data.py` всегда использует безопасный режим без замены.

## Правила идентичности песен

Идентичность песни определяется нормализованным названием, годом выпуска и неупорядоченным набором исполнителей. Регистр и лишние пробелы при сопоставлении не учитываются, исходное написание сохраняется. Разные версии песни должны иметь уточнение в названии.

Одна и та же песня, встречающаяся в нескольких годовых рейтингах, хранится в `songs` один раз, а её позиции — отдельными строками в `ranking_entries`.

Если для существующей песни отличаются язык или страна, импортёр выводит конфликт и прекращает импорт. Аналогично он останавливается при подозрении на конфликт идентичности: одинаковые название и год выпуска, но разные наборы исполнителей. Такие случаи нужно разрешить вручную в исходных данных.


## Аналитика

Модуль `src/analytics.py` рассчитывает показатели непосредственно по таблицам SQLite — отдельные таблицы со статистикой не создаются.

```python
from src.analytics import get_song_statistics, get_artist_statistics, get_hall_of_fame

songs = get_song_statistics()
artists = get_artist_statistics()
hall_of_fame = get_hall_of_fame(threshold=3)

for song in songs[:10]:
    print(song.title, song.artists, song.total_points, song.best_position)
```

Для песен рассчитываются число попаданий в годовые рейтинги, лучшая и средняя позиция, средняя позиция с учётом отсутствия (штраф `top_size + 1`), суммарные баллы и позиции/баллы по каждому году. Баллы за позицию равны `top_size + 1 - position`; отсутствие даёт 0 баллов.

В статистике исполнителей совместная песня засчитывается каждому исполнителю. Число появлений исполнителя — количество его песен во всех годовых рейтингах; если в одном году у него несколько песен, учитываются все.

Для устойчивости присутствия песен рассчитываются количество рейтингов с песней, доля присутствия, самая длинная непрерывная серия и текущая серия. В веб-аналитике доступна сравнительная таблица всех песен, отсортированная по устойчивости присутствия. В карточке песни дополнительно показывается количество попаданий в Top-10; история позиций и серий видна на графике.

Hall of Fame по умолчанию включает песни, появившиеся в Top-50 не менее трёх раз. Годом включения считается год третьего появления. Порог можно изменить аргументом `threshold`.

## Excel-отчёт

После импорта рейтингов можно сформировать отдельную Excel-книгу с аналитикой:

```bash
python -m src.report
```

По умолчанию создаются две книги:
- `reports/music_analytics.xlsx` — общая статистика за всю историю;
- `reports/music_yearly_analytics.xlsx` — подробная аналитика с отдельными листами песен и исполнителей для каждого года.

Аналитика прогнозов формируется отдельно, чтобы не перегружать основную книгу:

```bash
python -m src.forecast_report
```

Команда создаёт `reports/music_forecast_analytics.xlsx`. Для неё должны быть предварительно импортированы фактические рейтинги и прогнозы.

Генератор также можно вызвать из Python и указать собственные пути:

```python
from src.report import generate_excel_report

report_path = generate_excel_report(
    db_path="database/music.db",
    output_path="reports/music_analytics.xlsx",
    hall_of_fame_threshold=3,
    interval_count=7,
    yearly_output_path="reports/music_yearly_analytics.xlsx",
)
print(report_path)
```

В книге формируются следующие листы:

- **Статистика песен** — только суммарные показатели за всю историю: число попаданий, лучшая и средняя позиции, средняя позиция с учётом отсутствий и общие баллы.
- **Статистика исполнителей** — только суммарные показатели за всю историю: число появлений, лучшая и средняя позиции и общие баллы. Совместные песни засчитываются каждому исполнителю.
- **Устойчивость исполнителей** — доля рейтингов с присутствием исполнителя, самая длинная и текущая серии последовательных рейтингов, максимум и среднее число песен за рейтинг, а также доля баллов самого результативного трека.
- **Зал славы** — песни, достигшие заданного порога попаданий.
- **Статистика по годам** — новинки, повторные попадания (продолжение серии), возвращения после пропуска и средняя позиция.
- **Состав по годам** — число песен и доли по странам, языкам, десятилетиям и интервалам года выпуска для каждого Top-50.
- **Общий состав** — те же распределения по всем уникальным песням за всю историю рейтингов.
- **Графики по годам** и **Общие графики** — диаграммы структуры и её динамики. На диаграммах показываются наиболее частые категории, остальные объединяются в «Другие»; полные данные доступны в таблицах.
- **Методика** — пояснения к расчётам.

Границы семи интервалов годов выпуска вычисляются один раз по минимальному и максимальному году среди всех песен и остаются одинаковыми для всех рейтингов. Это обеспечивает сопоставимость годовых распределений. Десятилетия группируются по календарным границам: 1987 год относится к 1980-м.

В статистике состава считаются **уникальные песни**: в годовом разрезе каждая песня учитывается один раз, даже если в ней несколько исполнителей. В общей статистике песня также учитывается один раз за всю историю. Если у песни указано несколько стран или языков, она входит в каждую соответствующую категорию, поэтому сумма долей по странам или языкам может превышать 100%.

В отдельной годовой книге для каждого рейтинга создаются листы `ГОД Песни` и `ГОД Исполнители`. На них показываются годовые показатели, накопленные общие баллы на конец года, дельты и статусы. Каждый следующий годовой лист — накопительный срез: он включает все песни и исполнителей, которые хотя бы раз появлялись с начала истории по выбранный год, в том числе отсутствующих в текущем рейтинге. Для отсутствующих текущая позиция и показатели позиции остаются пустыми, баллы за год равны 0, а накопленные баллы сохраняются. Строки сортируются по накопленным баллам на конец соответствующего года по убыванию; при равенстве применяется алфавитная сортировка. Поэтому лидеры и порядок строк отражают положение именно на конец выбранного года, а не современный итоговый порядок.

Изменение позиции рассчитывается как `позиция прошлого года - позиция текущего года`: положительное значение означает подъём. Для песен и исполнителей дельта позиции рассчитывается только при наличии объекта в обоих соседних рейтингах. Статус `NEW` означает первое появление в истории, `RE` — возвращение после отсутствия в непосредственно предыдущем рейтинге, `OUT` — песня или исполнитель ранее появлялись, но отсутствуют в текущем рейтинге; пустой статус означает присутствие и в предыдущем, и в текущем рейтингах. Для исполнителя показываются и лучшая, и средняя позиция его песен в каждом году. Серии устойчивости считаются по последовательности имеющихся рейтингов (а не по календарным годам); доля баллов лучшего трека показывает концентрацию результата в одной песне.

В годовой статистике новая песня впервые появляется в истории рейтингов; повторное попадание продолжает присутствие в непосредственно предыдущем доступном рейтинге; возвращение происходит после отсутствия в предыдущем рейтинге, если песня встречалась ещё раньше. Доли повторных попаданий и возвращений рассчитываются отдельно от числа записей рейтинга. Генератор только читает SQLite и не меняет данные.

## Аналитика прогнозов

Отчёт по прогнозам находится в отдельной книге `reports/music_forecast_analytics.xlsx` и содержит листы: сводка метрик, сопоставление прогнозов с фактическими позициями, неожиданные попадания, отложенные попадания, повторные прогнозы, нереализованные прогнозы и методика. Он формируется командой `python -m src.forecast_report` и не добавляет листы в основную книгу `music_analytics.xlsx`.

## Прогнозы

Книга `data/music_predictions.xlsx` содержит отдельный лист на каждый год прогноза. Заголовки и порядок пяти столбцов совпадают с книгой фактических рейтингов: `Исполнители`, `Песня`, `Язык`, `Страна`, `Год`. Позиция определяется порядком строк; список может быть неполным (например, 43 строки). Допускается добавлять новые годы, в том числе будущие.

Прогнозы хранятся в `forecast_years` и `forecast_entries` отдельно от таблиц фактических рейтингов. Это позволяет сохранять повторные прогнозы одной песни в разных годах. `src/forecasts.py` предоставляет `import_forecasts`, `get_forecast_analysis` и `get_delayed_forecasts`. Отложенное попадание определяется от года самого первого прогноза до первого фактического попадания; повторный прогноз в последующем году оценивается отдельно.

## Стриминговый Top-5

Книга `data/music_streaming.xlsx` содержит один лист `Стриминги` и три столбца: `Год`, `Исполнитель`, `Время прослушивания`. Позиция определяется порядком строк внутри каждого года; отдельный столбец позиции не требуется. Для каждого года допускается не более пяти исполнителей. Время задаётся целым числом минут; пустая ячейка означает неизвестное значение (`NULL`), а не ноль.

Стриминговые записи используют общий справочник `artists` и хранятся в `streaming_entries`. Импорт выполняется отдельно после загрузки фактических рейтингов:

```bash
python -m src.streaming
```

Импортёр проверяет, что все исполнители уже существуют в общем справочнике. Если найден неизвестный исполнитель, импорт прекращается без частичной записи. Повторный успешный импорт заменяет стриминговую историю данными из книги.

## Аналитика стримингов

После импорта фактических рейтингов и данных из `data/music_streaming.xlsx` сформируй отдельный отчёт:

```bash
python -m src.streaming
python -m src.streaming_report
```

`reports/music_streaming_analytics.xlsx` сопоставляет стриминговый Top-5 с исполнителями годового Top-50. Для каждого стримингового исполнителя показываются число его песен в Top-50, лучшая позиция песни, сумма баллов и производная позиция исполнителя в годовом рейтинге по сумме баллов. Лист «За всё время» агрегирует всех исполнителей, когда-либо входивших в стриминговый Top-5: число лет присутствия, среднюю/лучшую/худшую позицию, последнее появление, суммарное и среднее время прослушивания по известным значениям, а также накопленные показатели музыкального Top-50. Пустое время прослушивания исключается из расчёта минут, а не превращается в ноль. После импорта нового года (например, 2026) отчёт автоматически пересчитывает как годовое сравнение, так и сводку за всё время. Подробные правила и ограничения находятся на листе «Методика».


## Локальный веб-сайт

В проект входит локальный аналитический интерфейс на FastAPI. Он использует существующую SQLite-базу и аналитические функции проекта; отдельная frontend-сборка и платный хостинг не требуются.

Установка зависимостей (включая веб-приложение):

```bash
pip install -r requirements.txt
```

Подготовка данных при первом запуске:

```bash
python import_data.py
python -m src.streaming
```

Импорт стримингов может сообщить об исполнителях, отсутствующих в общем справочнике `artists`. В текущей версии импортёр намеренно не создаёт таких исполнителей автоматически: это существующее правило целостности данных.

Запуск сайта:

```bash
python main.py
```

Откройте `http://127.0.0.1:8000`. Документация API FastAPI доступна по адресу `http://127.0.0.1:8000/docs`. Для остановки сервера нажмите `Ctrl+C` в терминале.

Веб-интерфейс содержит разделы «Главная», «Рейтинги», «Аналитика», «Стриминги» и «Прогнозы». В разделе «Рейтинги» для выбранного года отображаются возрастной состав песен, распределение по странам и языкам: диаграммы показывают доли песен, таблицы — абсолютное количество. Возраст рассчитывается относительно года рейтинга: 0–3 года — актуальные хиты, 4–10 — устоявшиеся хиты, 11–20 — старые хиты, 21–30 — легендарные хиты, 31+ — классика. Для стран и языков одна композиция может учитываться в нескольких категориях, поэтому сумма долей может превышать 100%. Карточки песен и исполнителей открываются отдельными страницами. На главной отображается динамика новинок, повторных попаданий и возвращений, а также точность прогнозов. В аналитике доступны графики баллов ведущих исполнителей по годам, распределения по странам, языкам и десятилетиям выпуска. В разделе стримингов график минут прослушивания переключается вместе с выбранным годом. На странице песни отображается история её позиций в Top-50, а на странице исполнителя — динамика баллов и количества его песен в рейтинге. В разделе аналитики также доступны показатели устойчивости исполнителей (доля лет присутствия, длина серий, среднее число песен за активный год) и зал славы песен, попадавших в рейтинг не менее трёх раз. Отсутствие песни в конкретном году на графике истории позиции отображается разрывом, а не нулевой позицией. База `database/music.db` создаётся при импорте и не включается в архив исходников: её можно сформировать заново из файлов в `data/`.
