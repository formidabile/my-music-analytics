# Импортёр музыкальной статистики Excel → SQLite

Импортирует годовые Top-50 из единственной Excel-книги проекта в нормализованную SQLite-базу. Пользователю не нужно передавать пути или параметры командной строки.

## Структура проекта

```text
project/
├── data/
│   └── music_statistics.xlsx
├── database/
│   ├── schema.sql
│   └── music.db              # создаётся автоматически
├── src/
│   ├── database.py
│   ├── importer.py
│   ├── analytics.py          # расчёт аналитических показателей
│   └── report.py             # генерация Excel-отчёта
├── reports/
│   └── music_analytics.xlsx  # создаётся генератором отчёта
├── tests/
├── importer.py               # запуск только импорта
└── main.py                   # точка входа приложения
```

Положи единственную книгу статистики в `data/music_statistics.xlsx`. Это фиксированный путь относительно корня проекта; имя файла не нужно передавать при запуске.

## Структура Excel-книги

- отдельный лист на каждый год рейтинга (`2023`, `2024`, `2025` и т. д.);
- пять столбцов строго в указанном порядке: `Исполнители`, `Песня`, `Язык`, `Страна`, `Год`;
- несколько исполнителей, языков или стран разделяются точкой с запятой (`;`);
- порядок строк данных задаёт позицию в рейтинге: первая песня — позиция 1;
- на каждом листе должно быть ровно 50 полностью заполненных строк данных.

Для совместимости принимаются также прежние варианты заголовков: `Артисты`, `Название`, `Языки`, `Страны`, `Год выпуска`.

## Установка и запуск

Требуется Python 3.10 или новее. Установи зависимости один раз:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Обычный запуск проекта:

```bash
python main.py
```

Либо запуск только импорта:

```bash
python importer.py
```

Аргументы командной строки не используются. Оба способа читают `data/music_statistics.xlsx` и используют `database/music.db`.

## Поведение при запуске

1. Если базы ещё нет, она создаётся по `database/schema.sql`.
2. Импортёр проверяет всю Excel-книгу: обязательные поля, годы, структуру листов, Top-50, дубли и внутренние конфликты.
3. Если хотя бы один год из книги уже есть в базе, импорт по умолчанию останавливается. Ничего не пропускается и не перезаписывается.
4. При конфликте метаданных с уже сохранённой песней импорт останавливается и выводит список конфликтов. Данные базы не изменяются.
5. Изменения выполняются одной транзакцией. При ошибке во время записи транзакция откатывается целиком.

Повторный запуск безопасен: он не создаёт дубликаты, а сообщает, что рейтинг за этот год уже существует. Для полной замены рейтингов из книги требуется явное указание `replace_existing=True`. Например, из Python:

```python
from src.importer import run_project_import

run_project_import(replace_existing=True)
```

Обычный запуск `python main.py` всегда использует безопасный режим без замены.

## Правила идентичности песен

Идентичность песни определяется нормализованным названием, годом выпуска и неупорядоченным набором исполнителей. Регистр и лишние пробелы при сопоставлении не учитываются, исходное написание сохраняется. Разные версии песни должны иметь уточнение в названии.

Одна и та же песня, встречающаяся в нескольких годовых рейтингах, хранится в `songs` один раз, а её позиции — отдельными строками в `ranking_entries`.

Если для существующей песни отличаются язык или страна, импортёр выводит конфликт и прекращает импорт. Аналогично он останавливается при подозрении на конфликт идентичности: одинаковые название и год выпуска, но разные наборы исполнителей. Такие случаи нужно разрешить вручную в исходных данных.


## Аналитика

Модуль `src/analytics.py` рассчитывает показатели непосредственно по таблицам SQLite — отдельные таблицы со статистикой не создаются.

```python
from src.analytics import get_song_statistics, get_artist_statistics, get_hall_of_fame

songs = get_song_statistics()
artists = get_artist_statistics()
hall_of_fame = get_hall_of_fame(threshold=3)

for song in songs[:10]:
    print(song.title, song.artists, song.total_points, song.best_position)
```

Для песен рассчитываются число попаданий в годовые рейтинги, лучшая и средняя позиция, средняя позиция с учётом отсутствия (штраф `top_size + 1`), суммарные баллы и позиции/баллы по каждому году. Баллы за позицию равны `top_size + 1 - position`; отсутствие даёт 0 баллов.

В статистике исполнителей совместная песня засчитывается каждому исполнителю. Число появлений исполнителя — количество его песен во всех годовых рейтингах; если в одном году у него несколько песен, учитываются все.

Hall of Fame по умолчанию включает песни, появившиеся в Top-50 не менее трёх раз. Годом включения считается год третьего появления. Порог можно изменить аргументом `threshold`.

## Excel-отчёт

После импорта рейтингов можно сформировать отдельную Excel-книгу с аналитикой:

```bash
python -m src.report
```

По умолчанию файл сохраняется в `reports/music_analytics.xlsx`. Генератор также можно вызвать из Python и указать собственные пути:

```python
from src.report import generate_excel_report

report_path = generate_excel_report(
    db_path="database/music.db",
    output_path="reports/music_analytics.xlsx",
    hall_of_fame_threshold=3,
    interval_count=7,
)
print(report_path)
```

В книге формируются следующие листы:

- **Статистика песен** — суммарные показатели, позиции и баллы по каждому году, а также изменение позиции и баллов относительно предыдущего рейтинга.
- **Статистика исполнителей** — число попаданий, лучшая и средняя позиции, баллы по годам и их изменение. Совместные песни засчитываются каждому исполнителю.
- **Устойчивость исполнителей** — доля рейтингов с присутствием исполнителя, самая длинная и текущая серии последовательных рейтингов, максимум и среднее число песен за рейтинг, а также доля баллов самого результативного трека.
- **Зал славы** — песни, достигшие заданного порога попаданий.
- **Статистика по годам** — новые и повторные песни, доля повторов и средняя позиция.
- **Состав по годам** — число песен и доли по странам, языкам, десятилетиям и интервалам года выпуска для каждого Top-50.
- **Общий состав** — те же распределения по всем уникальным песням за всю историю рейтингов.
- **Графики по годам** и **Общие графики** — диаграммы структуры и её динамики. На диаграммах показываются наиболее частые категории, остальные объединяются в «Другие»; полные данные доступны в таблицах.
- **Методика** — пояснения к расчётам.

Границы семи интервалов годов выпуска вычисляются один раз по минимальному и максимальному году среди всех песен и остаются одинаковыми для всех рейтингов. Это обеспечивает сопоставимость годовых распределений. Десятилетия группируются по календарным границам: 1987 год относится к 1980-м.

В статистике состава считаются **уникальные песни**: в годовом разрезе каждая песня учитывается один раз, даже если в ней несколько исполнителей. В общей статистике песня также учитывается один раз за всю историю. Если у песни указано несколько стран или языков, она входит в каждую соответствующую категорию, поэтому сумма долей по странам или языкам может превышать 100%.

Изменение позиции рассчитывается как `позиция прошлого года - позиция текущего года`: положительное значение означает подъём. Для песен и исполнителей дельта позиции рассчитывается только при наличии объекта в обоих соседних рейтингах. Баллы отсутствующего объекта равны нулю, поэтому изменение баллов отражает как изменение места, так и появление/исчезновение из Top-50. Для исполнителя показываются и лучшая, и средняя позиция его песен в каждом году. Серии устойчивости считаются по последовательности имеющихся рейтингов (а не по календарным годам); доля баллов лучшего трека показывает концентрацию результата в одной песне.

На листе годовой статистики новая песня — та, которая впервые появилась в рейтингах в этом году; повторная — та, что встречалась в любом более раннем рейтинге. Доля повторов рассчитывается как количество повторных песен, делённое на число записей рейтинга. Генератор только читает SQLite и не меняет данные.
